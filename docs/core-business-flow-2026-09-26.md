# 核心业务流架构与完成边界

日期：2026-09-26。

2026-09-27 更新：新版操作及计算语义见 [核心业务使用及架构](core-business-evolution-guide.md)，验证见 [本轮实施记录](core-business-evolution-progress.md)。

## 当前业务主链

平台当前以一个模块化单体承载核心业务：

1. **产品事实层**保存产品身份、具体配置和不可丢失的 Excel 来源。
2. **搭配知识层**保存适用、配套、共享、条件、数量范围及版本依据。
3. **项目配置聚合**保存房间、系统、角色需求、实际设备、配套分配和拓扑引用。
4. **确定性计算层**由 Python 检查兼容、共享、容量与分配，ZEN 只执行已维护的数量公式。
5. **业务输出层**从同一项目配置生成设备使用投影、采购清单和拓扑，不另存第二份可独立修改的清单。

前端调用 API 完成业务操作；后端业务服务不直接依赖浏览器状态。登录、权限、组织、审批和运维部署没有进入当前计算模型，后续增加这些能力时不应改写项目配置语义。

## 已闭环的核心能力

- 459 条产品来源都有明确整理结论，原始来源和冲突可追溯。
- 系统需求可以选择独立产品，也可以显式关联已有设备。
- 配套需求先检查，再由售前选择新增型号或关联已有设备；不会自动把全部候选加入清单。
- 共享服务器以设备实例计数，多个系统引用同一实例只生成一条部署项；采购数量由供货分配决定，客户已有设备不进入采购。
- 软件、授权、硬件和配件分别计量；资源需求可以交给配套服务器承担。
- 搭配知识支持业务化快速录入，常见适用、配套和共用关系不再要求维护者先理解完整内部字段；高级条件仍通过同一知识模型保存。
- 项目检查同时返回兼容、共享、容量、缺件、设备使用明细和待确认事项。
- 项目按“需求、选型、配套、校验、输出”计算统一进度；资料不足允许保存草稿。版本 3 区分已知检查、知识覆盖和人工确认；满足条件后由用户显式确认具体保存修订。
- 业务清单保留产品型号、规格、数量、服务对象、原资料价格字段及工作表行号，与拓扑共用同一份项目配置。
- 产品和知识更新不会静默修改旧项目；只有按最新资料重新检查并保存才产生新版本。

## 仍属于核心业务、尚未完成的部分

这些工作继续优先于登录和权限：

1. **真实业务知识确认**：当前没有已确认共享知识，红盾 Windows 与会议预约共用服务器仍只能判为资料不足；音视频、线材、授权和定制产品的真实搭配也未整理完整。
2. **企业报价口径**：来源里可能同时存在市场参考价、最低客户价等字段。系统目前完整展示来源值，但没有折扣、税率、渠道、区域、有效期和审批价政策，因此不能自动选择最终报价。
3. **标书需求与偏离表**：尚未建立“标书条款—参数要求—所选产品参数—偏离结论—出处”的项目级结构，也未生成正式偏离表。
4. **正式改单文档**：现已提供配置修订比较、改单预览及结构化采购差异，但未生成公司正式改单文档或加入最终报价政策。
5. **正式文档输出**：尚未按公司 Excel/Word 模板生成报价单、清单、偏离表和改单；当前输出是结构化业务清单。
6. **完整音视频计算**：线材长度、端口、安装方式和定制制造参数仍需产品知识与现场条件后才能计算。

## 架构约束

- 业务判断继续放在普通 Python 服务中，外部模型只用于资料提取和说明。
- ZEN 继续限定为数量公式执行器，不承担产品兼容或共享结论。
- 项目配置是唯一业务事实来源；报价、偏离、改单和文档均应作为带版本的投影生成。
- 未知信息必须暴露为待确认，不能用默认型号、默认价格或模型猜测补齐。
- 登录、权限和审批后续包在业务接口外层，不侵入产品、知识和项目计算逻辑。
