# WPS 产品联想与改单插件

## 边界

- WPS 加载项只读取映射列、展示候选并写入用户声明为“插件填写”的列。
- 公式、合并单元格、未映射列、数量和备注不会被候选接受动作覆盖。
- 选中已映射的产品列后，加载项使用贴合单元格的内联编辑器；默认只显示灰色补全文本，Tab 接受唯一候选并进入下一产品行。
- 同型号多配置会自动展开内联列表，必须通过方向键、点击或 Enter 明确具体配置及资料来源；没有候选时 Tab 保持 WPS 原生跳格行为。
- 项目写入分为预览和确认。预览不修改草稿或项目，确认通过现有检查指纹、期望修订和幂等操作保存一个项目版本。
- 工作簿副本保留绑定；重新绑定到新项目时保留产品选择，但清除旧项目设备 ID。

## 服务端数据

启动时通过现有 SQLAlchemy 元数据创建 `wps_pairings`、`wps_access_tokens`、`wps_suggestion_feedback` 与 `wps_diagnostic_events`。模板配置和工作簿绑定使用带修订历史的 `configuration_entities`：

- `wps_template_profile`：字段映射、插件管理字段、标准化表头指纹及明确确认的目录批次/来源工作表。
- `wps_workbook_binding`：工作簿实例、模板修订、项目基线、草稿和已管理设备。

所有 `/api/wps` 业务接口要求个人 Bearer 令牌。配对码只能消费一次且十分钟过期；令牌可由服务端撤销。

## 同步恢复

同步指纹包含规范化工作簿行、模板修订、绑定修订、草稿修订和业务差异。项目、草稿或模板变化会返回明确冲突，不自动覆盖。确认操作及内部更新、检查、保存均使用派生的 `operation_id`；响应丢失后使用原操作 ID 重试会取得第一次结果，不会再次生成项目版本。

插件每次打开已绑定工作簿时都会读取服务端绑定回执。若项目版本已成功生成但隐藏页写回失败，服务端较新的绑定修订会恢复项目基线、草稿修订和行级设备标识，后续不会重新创建同一版本。

## 内联联想

内联编辑器使用无标题的 WPS 非模态 WebDialog，并根据当前 Range 的屏幕坐标覆盖单元格。浮层会跟随滚动、缩放和窗口位置调整；候选在空间足够时向下展开，否则向上展开。它只会在模板映射声明的型号、名称或说明列中打开，不修改公式、合并单元格及其他列。

首次使用需在“模板”页完成工作表、表头和字段映射，并根据最多 20 行预览明确选择一次产品目录批次与来源工作表。范围选择形成模板 v2 修订；历史 v1 模板仍可读取，但没有明确来源时空白行预测不会直接授权 Tab。之后选中映射列即可直接输入；键入查询按 150ms 防抖，空白行上下文预测立即发起，旧请求会被取消。当前行分区为空时会从上方最近的分区单元格继承；预测同时读取当前产品、上方最多八个和下方最多三个已确认产品，以便在表格中间插行时兼顾前后序列。

后端根据精确/前缀输入、系统、已确认知识关系、系列、型号族、相邻距离及原始产品清单顺序生成高、中、低置信度。排序同时识别 `A → B → ?` 短序列，用于区分同一上一产品在不同版本中的分支。系统身份必须精确匹配，基础版本不会因为名称是子串而冒充华为版本。模板确认来源后，候选先按 `import_id + sheet` 硬分区，再计算反馈和上下文分数，因此个人历史不能把范围外配置推到第一；范围内仍有多个具体来源或配置时不会自动选择。

“排序第一”与“允许 Tab”是两个独立判断。只有具体来源和配置唯一、高置信度、领先第二个不同产品达到安全分差，并且具有明确输入、已确认模板来源、个人确认历史或已确认关系等强证据之一，才显示灰字并允许一次 Tab 接受。未确认来源模板中的单份历史顺序可以改变候选排序，但不会单独授权自动填入。

内联 WebDialog 在工作簿会话内持续复用，选区变化只更新上下文、位置和内容。可操作候选出现时注册全局 `Application.OnKey("{TAB}", "PresalesTab")`；加载中、无候选、错误、切换工作表或关闭工作簿时恢复原生 Tab。浏览器输入和 WPS 宿主快捷键共享同一个补全协调器，每个会话操作先取得一次性 `operation_id`，避免一个按键被两个事件重复写入。

输入完整且唯一的产品名称或型号时，即使没有剩余灰字后缀，也可一次 Tab 填充整行；同名多型号，或无法由当前来源唯一解析的同型号多配置，会自动展开并要求明确选择。接受时会并行预取下一行，因此移动到同一输入列后复用已开始的预测请求。按方向键展开或切换候选，Escape 关闭浮层。连续上下文推荐会排除前后已经确认的型号，但手动输入仍可重复选择。

### 接受反馈与顺序学习

从第二个产品开始，成功写入工作簿后会异步上报一次幂等反馈：上一个产品、当时的首选、实际接受的具体配置和来源。服务端不保存输入的产品名称、需求文字、工作表名或分区原文；工作表与分区只参与不可逆摘要。首行没有上一个产品，不会上报无效的顺序关系。

学习排序依次采用当前工作簿的短序列上下文、同一模板修订的相同上下文、工作簿或模板的弱历史以及当前人员历史。短序列包含最近三个上文产品和一个下文产品，因此同一个“上一产品”在不同系统分支中不会互相覆盖。用户跳过原首选并明确接受另一项时，所选项获得正向权重，原首选获得负向权重。模板创建新修订后不会继承旧修订的模板级顺序。

反馈上报失败不会伪装成功或阻断已经完成的单元格写入。失败原因写入插件存储并在任务窗格明确显示；相同 `operation_id` 重试只生成一条反馈记录。

### 匿名诊断

插件把查询耗时、候选数量、灰字就绪、焦点丢失、Tab 注册/恢复、接受结果和受控错误码写入共享诊断队列。事件使用随机安装 ID 和会话 ID，不包含查询文本、客户名称、工作表文字、备注或错误堆栈；服务端也不保存诊断事件对应的人员姓名。

任务窗格每次最多提交 50 条，`event_id` 保证重试幂等。上传或本地队列损坏会在任务窗格显示真实错误，不影响已经完成的单元格写入。服务端在每批写入时删除 30 天前的数据，并提供 `presales-wps-purge-diagnostics` 命令覆盖长期无请求环境。
