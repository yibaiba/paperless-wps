# 产品已含内容计量：实现与验收

日期：2026-09-28。

## 实现范围

沿用 Python 模块化单体、既有项目版本及工作草稿。不新增模型调用、服务或数据库表。

- 具体产品配置增加 `included_items`：稳定包含项 ID、名称、具体配置、软件／授权／硬件／配件类型、每单位包含数量、可满足的需求标识、状态和证据。
- 不完整事实可存草稿；确认时要求配置、数量、需求标识及证据齐备。目标必须存在，不可包含自身；同一目标的活动包含项合并维护，避免同一数量重复记账。
- 旧客户端更新配置但未提供新字段时保留包含事实；明确提交空数组才清空。事实进入既有配置修订，不能注入伪造项目快照。
- 项目使用 `included_allocations` 显式关联宿主、包含事实、配套需求及数量，绑定宿主具体配置和修订；并记录本次采用依据。
- 计算语义 v3 复用配套需求计算，再计算已含抵扣。需求返回另行配套量、有效已含抵扣量、合计已分配量、缺量和多余量。只查询项目中保存的配置事实，不用产品名称推断。
- 同一宿主包含项的分配跨需求合计；重复占用或数量缩减导致超量时，相关抵扣均不计入并报告冲突。未知条件不能因抵扣变成通过。
- 新抵扣通过共享业务操作校验，不能超过当前缺量及可用包含量。既有采购项不自动删除；后续数量变化出现多余时明确提示。
- `included_link`、`included_remove` 在网页与 MCP 共用，支持幂等重试、原子批次、版本冲突、工作草稿、撤销重做和保存重开。
- 删除宿主清理其抵扣；需求失效的抵扣可以在配套页移除。包含项不成为采购设备或图形节点，拓扑仍引用原宿主。

使用路径：产品整理 → 具体配置 → 编辑 → 此配置已含的软件／配件；项目 → 处理问题与配套 → 选择配套 → 产品已含内容抵扣。

## 业务边界

此轮完成的是明确包含关系的数量抵扣，不自动将包含项变为独立角色选型、可跨设备转移的授权、资源容量或递归部署拓扑。复杂的软件运行依赖及授权共用仍需相应业务知识和人工核对。

真实产品的包含数量、对应具体配置、适用范围与授权范围尚需资料确认。本轮没有新增真实已确认包含事实，也不代表真实项目整套搭配已经验收。未涉及桌面 Excel／WPS 显示重算验收。此前未提交的 Excel 导入改动保持保留。

## 后续完善：失效原因与原位重新核对

已含抵扣卡片现在逐条显示关联数量、有效抵扣量、宿主总含量、共关联量、采用修订、当前项目修订及两份依据。资料更新造成的失效不会仅显示“已关联”；同步中显示待检查，旧保存结果缺少细项时提示重新检查。

“修改数量／重新核对”复用同一批 `included_remove` + `included_link` 操作，保留关联 ID，并作为一次草稿修改和撤销步骤。后端校验失败时事务回滚，原关联和草稿修订不变；仍遵循既有同步失败反馈。确认不会自动刷新项目所用产品资料，采用的是当前项目的固定修订。

新增隔离测试覆盖失效原因投影、超量替换回滚、小数数量、修订确认、幂等重试及检查点撤销；前端验证稳定对象 ID、精确小数文本及不存在的原关联不能重建。相关回归批次 37 项后端测试通过（19.77 秒，每项／每批均 60 秒硬超时）；前端 38 项通过，类型检查、构建、Ruff 和差异检查通过。构建保留原有 Univer 大分包警告。

实际浏览器中，将隔离项目从旧包含依据 v2 更新至 v3，确认页面显示“已关联 1、有效 0”；点击重新核对并填写依据后变成有效 1、缺量 0。直接改为 0.5 后正确显示还缺 0.5；一次撤销恢复原抵扣。保存项目 v4 并刷新后仍显示采用 v3、有效 1、缺量 0。截图为 `重新核对-失效原因.png` 和 `重新核对-保存重开.png`。真实业务资料没有新增确认结论。
