## 交付内容

1. 工作簿说明/备注按范围保存为 material 修订，记录 SHA256、单元格、合并归属与原文；旧来源 ID 不变。产品关系、数量、推荐与已含事实复用同一证据类型及验证。
2. 选型前沿候选配套链发现输入，网页与 MCP 共用描述；采集、字幕、并发、话筒、地插和延长线显示业务名称。输入冲突与循环可定位；数量输入不当作产品硬件属性。
3. EG 与 AI 纪要增加定义和资料包草稿；9 条适用、1 条共享、3 条随附/内置事实均保留核对状态。版本变化进入更新批次，不自动停售或替代旧 C5。
4. 37 行参考案例固定到修订，通过显式映射关联设备、角色、配套或已含内容。网页对账与 MCP 分页结果共用服务。单台共享设备采购一次，整批数量与本行分配用量分别展示。
5. AI 系统可记录多个服务房间，部署位置与服务范围分开；不从房间数推定未确认的授权/字幕数量。

业务库原有 459 条来源、410 条关联、49 条阻塞、2 个已保存项目仍保留。新增一个37行参考案例。新增知识没有自动发布；所有试验项目、价格和共享规则均在隔离数据库。

## 双入口实操

真实 stdio 完成：建立房间/系统/需求、读取前置采集/字幕输入、生成并采用部分提案、显式选配、关联配套、37行分页对账、改单、保存重开及导出。相同草稿通过 HTTP 与 stdio 逐行对账一致。为检验37项全流程而显式选择的27个测试设备，不是声称系统凭现有知识自动生成了完整方案。

浏览器使用隔离 API `8021` 与网页 `5181`，实际完成：

- 上传 V2.2 副本，预览工作表，保存 C2:G4，检查合并归属和固定修订引用；未确认知识、未调用模型。
- 打开37行对账，修改映射说明，撤销、重做、刷新恢复；保存项目 v2。
- 运行网页方案生成及整批采用；页面显示“部分生成、资料不足”，未把原表当通过依据。
- 通过系统需求表单将采集房间数2改3；检查实际返回需要3、已有2、缺1；撤销恢复2。
- 从对账行直达设备，删除后出现“关联设备已删除”，撤销恢复27项设备。
- 导出并实际下载公司模板报价。下载文件74行、1个Logo、26处合并、63个公式，保留13%税运说明；合计公式明确返回“待确认”，没有以已知小计冒充总价。

## 逐项结果及真实缺口

## 复核修复

- 功能未确认或固定定义不包含该功能时，不能显示未启用通过。
- 已含分配必须自身检查通过才抵扣；重复引用在边界明确报错。
- 部分已含抵扣与新增采购混用时，不把整行标为已有/已含满足；对应失败回归已复现并修复。
- 原文单元格保留空白，旧修订不可改写；单位不同不直接计算数量差。
- 角色部分分配与整批部署分开；角色/配套重叠用量明确提示核对，不重复相加。
- 前端案例映射在对象创建之后原子提交，撤销与原项目版本互不覆盖。
- 工作簿异步选择按请求序号处理，失败重试保留相同幂等键；合并原文在选择表中去重，但引用ID不变。
- 从报价视图点击对账设备时直接切回清单并打开对应属性，角色与设备面板互不遮挡；已完成真实浏览器验证。
