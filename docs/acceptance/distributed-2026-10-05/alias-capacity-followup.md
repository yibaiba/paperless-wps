# 服务器角色引用配套：容量与共享复核

日期：2026-10-05。基线：`589beae`。本轮只调整业务计算及验证入口，排除并行 WPS 改动。

## 已复现的问题

同一服务器批次共 3 台，每台容量 128 GB。两个系统通过耗用型配套需求各分配 1 台，资源需求分别为 150 GB、40 GB；服务器角色通过已确认 `fulfilled_by` 引用相应配套。

旧行为把这些角色引用视为额外直接用途，退出按配套需求划分容量的路径，得到 `190 ≤ 384` 的通过结论，并把独立分配误认为共用。先加入回归，Python 与 ZEN 路径及角色额外资源三个用例均失败；无关直接用途的保护用例通过。

## 修复

- 角色满足投影保留具体配套需求 ID，不只保留上级角色 ID。
- 已确认角色引用归入对应配套分配，容量继续按实际分配数量计算：150/128 冲突，40/128 通过。增加未分配库存不会改变结论。
- 角色自己的资源进入对应需求；同一上级角色的其他配套不会继承该资源。
- 只标记角色的直接引用，不把该角色自己的下游配套也标为同一用途。
- 真实 shareable 关系及无关直接用途仍进入共享检查。没有共享依据不判通过。
- 用途标记改为返回新投影，不原地修改传入用途数据。未新增业务持久字段，未修改真实产品或知识。
