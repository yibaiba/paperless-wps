# 拓扑与配置业务逻辑梳理

日期：2026-09-24。状态：基于当前代码及页面的审查与建议，尚未实施重构。

## 业务目标

用户希望通过产品资料与拓扑，维护产品线、组合、必配、选配和共享条件，然后用于项目选型、辅材计算与清单。当前实现偏向具体方案画图，尚缺可复用的系统配置定义。

## 当前断点与证据

| 断点 | 代码/页面事实 | 影响 |

## 建议的业务对象

1. **产品及规格**：稳定产品标识、型号、规格/配置、参数、图片；一个产品可有多个资料来源，来源冲突保留。型号相同不自动认定同一个配置。
2. **产品线与适用范围**：表达哪些产品可以用于哪些产品线，允许多对多；产品所属目录不决定部署时能否共用。
3. **系统配置模板**：版本化维护角色、固定产品/候选集合、必选/可选项、适配条件、容量、配套数量与接线要求。
4. **项目方案**：引用具体模板版本，包含实际房间、系统实例、已选产品配置、数量、共享部署及项目例外。
5. **图纸视图**：展示上述对象、端口与关系，保存坐标/外观，允许业务实体出现在不同视图。

现有导入记录不能直接批量合并或重新编号。先增加可确认的映射，保留旧来源引用及历史快照。图纸迁移前需处理现有版本、未保存修改和撤销语义。

## 两条明确的操作流程

### 维护产品线知识

选择产品线 → 新建系统模板 → 添加角色或固定产品 → 为角色指定候选型号/规格 → 定义关系、条件及依据 → 输入样例试算 → 保存模板版本。

产品节点可以直接使用具体型号；只有存在选型空间的部分才引入角色和候选，避免强迫所有配件都经过额外建模。未确认关系可以保留为草稿，但不得当作已验证规则参与结果。

### 制作项目清单

建立项目/房间 → 添加系统并选择模板版本（也允许手工配置）→ 填席位、功能、数量等项目条件 → 选择候选产品/规格 → 计算并查看依据和缺项 → 应用确认的配套 → 同步显示清单与拓扑 → 保存项目版本。

清单与图纸编辑同一套项目配置；草稿预览随业务改动更新，保存生成版本。移动位置、更换图片不触发配套计算；改变数量、规格、角色、共享条件时重算相关配置。

## 必须明确的交互语义

- 模板中多选几个服务器型号，表示可选候选时不能全部计入项目；项目中多选实际产品则加入清单。
- “必须有服务器”定义角色需求；“A/B 二选一”定义候选关系；“网口连接”定义连接要求，三者分别维护。
- 系统归属由业务关系表达，拖入视觉容器不应无提示改变归属；明确的“移入系统”操作才修改业务对象。
- 产品能用于两条产品线，不代表一个实际服务器可以同时承载两个系统；共享需记录部署、容量及软件条件。
- 同一部署服务多个系统只计一次；同型号的两台独立设备计两台。引用展示与复制新设备应有不同操作。
- 线材用已确认的连接类型、端点/端口数量、实际线路长度和损耗规则计算，不能使用画布距离。缺少必要输入时展示未计算项。
- 定制产品以具体配置项记录尺寸、材料、加工条件和计算依据；项目修改不直接覆盖标准产品资料。
- 产品或模板更新展示差异，由维护者更新项目引用；旧项目版本仍可重现。
- 当前“图形绑定”保留为导入旧图的工具；日常从产品库或模板添加时自动关联业务对象。

## 页面结构建议

产品资料：来源、规格、参数、图片、适用产品线。

系统模板编辑器：左侧产品/角色库，中间拓扑，右侧所选对象业务属性，下方关系与试算结果。接线/配置关系可分层显示。

项目方案编辑器：左侧房间/系统树，中间清单或图纸视图，右侧所选配置，下方配套计算与缺项。添加产品使用可持续操作的停靠面板；需要完整资料时另开详情。

## 实施顺序和验收

1. 优先补齐系统模板、角色/候选和条件关系；沿用现有产品来源、规则执行与绘图能力。
2. 用一个已确认边界的无纸化子系统验证模板；具体型号、容量和适配依据须来自已核对资料，不能把示例条件当业务事实。
3. 贯通项目配置、图纸和实时清单；保留已有数据与版本，明确图形复制/删除含义。
4. 逐步接入共享资源、端口/线材和定制配置，分别验证业务样例。

验收包括：候选只选一项不会全加入；同产品跨产品线使用不复制产品主数据；共享部署只计一次、独立部署分别计数；图纸移动不改变业务；修改数量时图纸/清单/计算一致；更新模板不静默改变旧项目；来源冲突保持可追溯。
