## 提交范围

需求驱动提案生成、持久化、替代方案、整批采用、改单保护、网页与 MCP 衔接；同时纳入它依赖的先前未提交产品维护、价格版本、知识包维护和已含内容功能。保留现有接口及固定快照。

并行 WPS 插件代码、测试、说明、启动脚本以及 main.py 中 WPS 路由均未纳入本提交。没有提交业务数据库、私有配置或测试业务写入。

## Review 发现并修复

1. **P1：不同复用方案发生 ID 碰撞。** 两台相同配置的现有设备都可复用时，方案设备列表相同，但角色指向不同。旧摘要只散列设备 ID、型号、数量及配套分配，两个方案得到相同 ID；按 ID 采用会取第一个方案。现在 ID 覆盖完整提案配置及问题，测试验证选择第二个方案后确实关联第二台已有设备，且没有新增设备。
2. **P2：删除系统、角色或设备后留下悬空选型偏好。** 后续生成可能因不存在的需求触发异常，修改需求也可能被已删除的复用设备阻断。删除操作现在同步清理该对象的偏好、复用引用、功能确认和需求来源，保留其他对象的偏好；旧修订及撤销检查点不改写。测试覆盖删除角色、系统及单台可复用设备。
3. **P1：房间、项目级待确认理解可进入有效需求。** 原校验只检查系统与角色，未覆盖房间数量、项目数量和预算。现在按对象及字段路径比较变更；未确认的理解不能改变这些有效输入。测试先复现错误接受，再验证返回 422、整个批次回滚，明确确认后才能修改。

三处问题均有修复前失败、修复后通过的回归。当前复核范围未发现尚未处理的阻断提交问题；这不代表穷尽所有缺陷。
