# 配套角色型号约束前置筛选 review

回归源码基线：`1ad8ccc`（包含上轮配套来源修复 `b7090ad`，并保留同期 WPS 提交）。本轮继续检查角色经配套满足时，明确型号要求、排除项、已有设备和人工锁定的一致性。仅修改业务生成服务和隔离测试；未修改业务资料、数据库结构或前端。

## 复现

隔离知识包提供两个已确认服务器候选，服务器角色由终端的 `server` 配套需求满足。角色明确指定其中一个型号后，完整检查最终能选择符合要求的型号，但生成器仍先按两个候选计算推荐完整性，错误留下 `recommendation_missing`，并把提案标为非标准方案。排除一个候选也存在相同问题。

`before.log` 保存修复前的有效失败断言；测试数据中的第三个配置与资料来源均通过正常维护接口建立，不修改真实资料。

## 修复及复审

- 抽取直接选型现有的型号／排除项／来源筛选函数，配套和直接角色选型共用。筛选发生在推荐排序之前。
- 配套只读取真正通过此需求满足的角色约束；多个角色的硬条件取交集。父产品自身的型号与排除项不会误用于配套。
- 已有候选全部与明确约束冲突时，返回 `accessory_candidate_conflict` 及角色依据，不随意创建设备。没有已知可用候选仍保留原有资料不足路径，不能据此证明业务无解。
- 筛选后的配置才进入已有设备复用及缺量生成。被排除的已有设备不会自动采用或删除。
- 人工锁定路径优先，仍保留人工设备并由完整检查报告与新需求的冲突。没有明确型号要求时，多候选仍需要推荐依据，不伪造标准方案。
- 来源矛盾、共享与容量、供应状态和完整业务检查继续生效。公共接口和原快照不变。
