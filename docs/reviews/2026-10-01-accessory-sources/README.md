# 配套生成采用角色来源要求 review

基线：`2603718`。本轮检查通过配套满足的角色、资料来源选择、已有设备复用与缺量补购。隔离测试数据与业务库分开，未改动 WPS 模块及原有未跟踪 review 目录。

## 已复现并修复

服务器角色由软件／终端的 `server` 配套需求满足时，角色偏好中的 `source_id` 没有传给配套设备生成器。即使指定来源属于唯一合法候选配置，配套仍采用默认来源，最终才产生客户选型冲突。此前直接角色选型的来源筛选不能覆盖这条路径。

修复将该配套需求所满足角色的来源要求传递到三个步骤：

1. 配套候选必须关联指定来源。
2. 自动复用的已有设备必须采用指定来源。
3. 新增配套及复用后的缺量补购均采用指定来源。

来源要求只从对应系统、父角色和 `need_key` 的满足关系取得，不把终端自身的来源当成服务器来源。范围内存在多个实际消费角色时，一并读取相关角色要求，不只取第一条；其他系统或其他需求的角色不参与。

同一需求对应的角色指定互相矛盾的来源时，提案返回 `accessory_source_conflict`、角色依据和待处理字段，不任取一个来源采购。人工锁定的设备继续走原有保护路径，保留选型并由正常检查提示冲突。无指定来源时沿用原语义。
