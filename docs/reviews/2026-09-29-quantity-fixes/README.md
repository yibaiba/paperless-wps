# 角色数量与共享配套抵扣修复（2026-09-29）

基线：`b3175c3`。修复前两条独立 API 复现均失败，见上一轮 `../2026-09-29-quantity-review/`。本轮只修改数量检查及其回归测试，不修改业务数据库、真实知识或工作区内独立的 WPS 开发内容。

## 修复行为

1. **直接绑定设备的角色漏掉数量检查（P1）**
   直接 `device_id` 与多设备 `allocations` 统一为数量分配输入。以系统固定定义／知识包引用的数量依据调用现有 ZEN 计算，再与已分配量比较。32 席终端改成 1 台、需求从 32 席改为 48 席，都会报告明确数量冲突；恢复正确数量后可通过。缺少数量依据或输入时返回资料不足，处理动作分别指向内部定义或项目需求。
   已确认且实际关联到配套的角色复用配套数量检查，避免服务器出现重复计量；拆分角色中只关联一部分设备，不能豁免其他未关联部分。旧知识包继续使用固定定义修订；无包项目使用固定定义快照，只有明确刷新才更新。

2. **同一共享设备重复抵扣同一需求（P1）**
   按“需求 ID＋设备 ID”累加分配，应用新关联时校验累计数量。设备数量 1、需求数量 2，第二次分配同一台设备返回 422；不会虚报已满足 2 台。
   重新检查也识别历史重复分配和设备减量后的超额关联。无效分配组保留原记录并报冲突，不计入有效抵扣，不截断数量或静默删除。设备数量 2 时，两次分配各 1 仍合法，需求满足后的重复应用不新增关联。不同需求之间的共享、耗用型配件的全局数量检查保持原逻辑。
