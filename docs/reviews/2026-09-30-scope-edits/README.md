# 需求范围编辑继续 review 与修复

基线：`2ffbe29`。本轮沿需求填写、生成、改单、撤销及保存路径检查；真实业务库没有被修改。WPS 工作区改动和其他未跟踪 review 目录未纳入本轮。

## 已复现并修复

### 1. 房间／项目数量无法通过网页正确录入

后台需求描述已经返回 `room`／`project` 作用范围，但前端只按 `system`／`role` 处理，其他范围被写入没有角色标识的环境字段；系统设置接口也未接收这些范围的输入，草稿操作投影未同步它们。表现为页面填写规模后仍无法用于数量生成。

修复：前端按四种作用范围读取、展示和提交；系统设置预览及业务操作支持可选 `room_inputs`（当前所选房间）和 `project_inputs`；网页使用既有 `requirements_patch` 持久化范围变化。省略字段保留原值，明确空列表表示清空该范围，未把空白解释为零。切换房间读取目标房间，新房间保留未知，其他房间参数和角色环境不受影响。共用参数构建和替换函数，避免各范围各写一套字段处理。

### 2. 有数量参数的房间删除失败

删除操作移除了房间，却保留 `room_inputs[room_id]`，最终配置校验报“房间输入引用了不存在的房间”，整笔操作失败。

修复：与房间删除原子清理其输入，系统解除房间关联，其他房间及项目输入保留。验证幂等重试、检查点撤销恢复原房间及参数。

### 3. 同角色多条需求的资源被批量覆盖

`requirements_patch.systems[].roles[].resources` 仅携带角色 ID；同一系统存在多条同角色需求时，原实现修改所有匹配项，可能抹掉不同需求的资源量。环境编辑已有歧义处理，资源编辑未遵守相同语义。

修复：匹配多项时明确报错，要求使用现有 `requirement_put` 按需求 ID 编辑；单项资源修改仍支持。失败保持整个草稿不变；明确修改一项不影响另一项。资源更新函数返回新的配置及需求对象，不修改传入对象。
