# 人工来源选择与已有设备复用范围 review

基线：`6c23b6a`。继续检查方案生成、人工选型、复用分配、保存重开与撤销。使用隔离 SQLite 数据库和测试产品，不修改真实业务库；未纳入 WPS 工作区改动及其他未跟踪文件。

## 复现与修复

### 1. 人工修改资料来源在重新生成时被覆盖

同一配置有两个已关联来源时，生成器默认选择排序靠前的来源。人工通过 `device_put` 采用另一来源后，只因配置 ID 未变化，原编辑服务没有标记选型锁定；重新生成又选择原来源，覆盖维护者已经采用的资料。

修复将明确的来源变化纳入现有选型锁定语义，配置 ID 与来源 ID 一起决定是否是人工选型修改。不新增锁定字段；既有角色及配套生成路径复用该标志，保留人工来源。数量锁定标志不因来源修改被设置；按现有人工选型保护流程，后续数量变化应由检查提示并明确改单。仅改备注不会锁定选型，自动生成仍能随席位变化计算数量。

新增测试分别覆盖直接角色的终端与通过配套满足的服务器：网页编辑预览与 MCP 编辑结果一致，生成后来源保留，保存新版本、重建草稿、重新生成后仍保留；撤销到原检查点恢复原来源及原自动选型状态。

### 2. 指定角色的复用许可扩散到其他配套需求

服务器角色的 `fulfilled_by` 明确对应终端的 `server` 配套。若还有一个 `control` 配套需求，且候选配置相同，原生成代码只核对父角色和系统，漏掉配套需求键，因此把“允许服务器角色复用客户已有主机”的许可同时用于控制主机。即使采用独立部署，也会将两个不同用途关联到同一台已有设备，少列一台采购。

修复同时匹配系统、父角色和 `need_key`。只有该角色明确对应的配套需求能继承其已有设备复用许可；原父角色的显式复用许可及显式共享方案机制不改变。

新增测试在同一系统中建立两个目标型号相同的不同配套需求：服务器需求继续使用客户已有设备，控制主机生成另一个设备 ID 并单列采购 1 台，已有设备供货来源仍为客户已有。

## 复审与边界

复审了自动选型与人工选型、配置 ID 与来源 ID、角色与配套需求范围、独立部署与显式共享，以及恢复历史检查点后的锁定状态。未引入按同型号自动合并，也不把一次角色复用许可当作全部需求的共用依据。

本轮未改前端代码，未重新执行前端构建或真实浏览器验收；网页接口和 MCP 共用编辑链路有自动测试，不能替代点击验收。真实客户项目对账、真实共享依据和桌面 Excel／WPS 重算不包含在本轮结论中。
