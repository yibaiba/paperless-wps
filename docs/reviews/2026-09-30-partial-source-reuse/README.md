# 指定来源下的部分复用 review

基线：`01690c8`。本轮检查角色候选、已有设备批次、来源约束、缺量补购及人工分配保护。采用隔离数据库，不修改业务资料，也不改动 WPS 功能或原有未跟踪 review 目录。

## 已复现的问题

需求为 32 台；客户允许复用两批同配置设备，各 16 台，其中一批来源符合明确要求，另一批不符合。原生成器仅按配置筛选已有批次，将两批一并组合。最终检查发现来源冲突后，跳到“全部新增”的分支，采购了 32 台，没有尝试“符合来源的 16 台＋补购 16 台”。

调整批次顺序仍会发生；先生成方案、再增加指定来源约束也会发生。已有合格数量 16.5 时同样直接采购 32，而不是仅补 15.5。修复前 6 个业务断言失败，见 `before.log`。

## 修复

在已有设备的复用候选入口同时应用明确的来源约束，再执行既有可用数量计算和余量补购。未指定来源时维持原逻辑；不修改已有设备的来源、数量或客户已有供货状态。不符合来源的设备仍保留在项目中，未擅自删除。

人工明确指定的拆分分配仍走已有保护路径：保持人工组合，并返回来源冲突，不借此次筛选静默重排人工设备。
