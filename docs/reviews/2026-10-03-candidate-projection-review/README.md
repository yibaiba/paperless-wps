# 候选与项目组合检查一致性复核

## 范围与结论

继续复核 ZEN 的项目候选路径，重点对照正式项目检查的输入投影和返回对象身份。本次为实现者代码复核，发现并修复两项可复现问题，没有修改真实业务库、知识结论、前端或 WPS 功能。

## 发现与修复

### P2：候选组合检查遗漏系统级输入

正式项目检查先执行角色数量分配投影，再用 `prepare_inspections` 合并系统输入、角色环境和固定用途检查。候选路径只做了前一步，因此系统中已经填写的环境不会进入组合规则触发判断。

隔离复现：组合仅在 Windows 环境下禁止两种设备共同出现。正式检查在 Windows 下返回冲突，在 Linux 下不触发；候选却把两者均显示为资料不足。

修复：候选调用同一 `prepare_inspections` 投影后，再计算配套和组合。该过程只处理临时配置，不修改项目需求或采购设备。新增三种环境回归，修复前 Windows/Linux 两项失败，未填环境项通过；修复后全部通过，未知仍为未知。

### P2：候选返回计算临时角色 ID

角色显式分配数量时会生成计算切片。正式项目检查通过 `restore_requirement_ids` 还原角色身份，候选路径未还原，组合明细的 `requirement_ids` 返回了项目里不存在的 UUID，调用方无法据此定位原角色。

修复：候选保留分配投影的映射，并用现有还原函数处理组合检查结果。新增回归确认目标角色返回 `r2`，而非内部临时标识；修复前失败，修复后通过。没有改变分配量或设备身份。

## 验证

本轮共覆盖 44 个不同后端用例：

- 新增候选投影回归 4 项，原组合回归 16 项；与原 stdio 用例合批执行为 21 passed，11.69 秒。
- 决策版本、用途检查、知识包范围回归 22 passed，9.11 秒。
- 随后扩展 stdio 测试为无条件组合及系统输入＋显式数量分配两种情形，2 passed，8.49 秒。真实启动 MCP 子进程，验证 `catalog_search` 与 HTTP 的完整返回一致，并执行 `list_check`、`list_get`；重复的原 stdio 用例不重复计入上述 44 项。

每项设置 `--timeout=60`，每批由 `subprocess.run(timeout=60)` 硬限制。全部使用隔离测试数据库。修改文件通过 Ruff 和 `git diff --check`。

MCP 查询使用摘要结构；角色 ID 还原由 HTTP 候选明细回归验证，未为测试扩展公共响应字段。本轮未修改前端，因此没有重复生产构建或浏览器验收；真实客户清单及桌面 Excel/WPS 仍不属于本次验证结论。
