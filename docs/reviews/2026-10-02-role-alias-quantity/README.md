## 已确认问题（未修复）

[P1] 配套批量设备被多个角色别名引用时，方案生成抛出 422。

通过正常 API 创建隔离知识包：父角色有一个已确认、系统范围、消耗型固定数量配套需求；服务端角色明确由这个需求满足。项目中有两个该服务端角色的需求引用，均指向同一个已确认的父角色／配套需求。数量为 1 时生成、采用与检查可执行；数量为 2 时 `list_plan` 返回 422：“共用设备请按单台实例维护，再关联多个角色”。

原因：`planning/fulfillment.py:71` 对多个角色逐个调用 `bind_role`，使用相同批量设备的 `device_id` 建立直接关联。`schemas.py:134-137` 将这种表示视为真实多角色共用非单台设备，拒绝 Configuration。生成器因此产生无法通过自身模型校验的中间配置，没有返回可读的方案提案／检查事项。

这里不能简单删除单台共享校验；修复需要在角色满足投影中区分“同一配套需求的别名”与“真正独立用途或共享部署”。还应复核 `calculation/role_allocations.py:15-18` 在跳过已满足别名之前累计设备数量的逻辑，以免只改表示后又出现重复占用误报。后者本轮仅静态定位，未声称已完成端到端复现。
