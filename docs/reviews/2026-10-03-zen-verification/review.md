## 发现、修复与复核

1. **已选产品重新查候选被误判为资料不足。** 候选试算临时改绑角色后，原设备仍在实际清单中，其新产生的无用途检查混进候选结果。复现中已确认适用且满足必选的配置返回 `unknown`，证据同时有“组合满足”和“资料待确认”。现仅汇总候选触发、候选配套触发或指向当前角色的组合；完整项目检查仍保留无用途设备的缺口。
2. **MCP 缺少数量问题的原因。** 角色数量未确认时，服务已有 `combination_notice`，但 `catalog_search` 摘要只转发状态与适用依据。兼容增加 `combination_notice`、`combination_checks`、`input_checks`，保留分页和工具名称。
3. **修复过程中的反向复核。** 初版只按触发设备和目标角色筛选，会遗漏“当前角色的配套设备触发的组合”。新增失败回归后补充真实触发角色 `trigger_requirement_ids`，沿用临时角色 ID 还原；确认其他设备施加的约束和配套间接触发的互斥均不能被过滤。

变更只涉及候选相关性和检查信息传递。没有删除实际设备、压低全项目问题数、改写已保存资料或在 ZEN 出错时转用 Python 假成功。无新增依赖。
