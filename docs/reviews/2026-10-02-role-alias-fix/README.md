# 配套角色别名生成与数量计数修复

回归基线见 `baseline.txt`（0acd93a）。本轮修复此前两个已复现问题，保持 Python 业务编排与 ZEN 数量计算分工，不迁移规则引擎、修改数据库结构或业务知识。

## 修复

1. 同一批量配套设备可由多个已确认的角色满足关系引用。批量设备使用现有 `allocations` 表达其实际配套分配数量，避免直接关联被误判为多角色共享非单台设备而返回422。单台实例继续保留原关联表示。
2. 确认且已实际关联的角色别名不再额外累计为库存占用；真正的配套占用仍由配套分配检查核算。单个别名自身超过设备数量仍报冲突，未确认关系、未实际关联及普通角色仍走原数量检查。

多个配套需求对应同一批设备时，消耗型分配相加，共享型按各需求分配量的最大值计入角色引用；这里只投影已经分配的数量，不建立共享许可或放宽容量检查。源设备数量、采购分配、价格和来源快照不因新增角色引用而增加。

人工明确修改的关联和数量继续保留。多个不同设备无法形成唯一角色关联时，继续提示待确认，不任取一个设备。单台共享的边界校验保留；没有放宽 `Configuration` 校验来掩盖错误。
