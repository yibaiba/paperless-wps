# 人工关联、配套分配与待确认需求修复

基线：`5414029`。对应上一轮 followup review 的 R1、R2、R3。业务数据库、真实产品资料、价格及知识未修改。

## 本轮修复

### R1：角色关联与设备生成来源分开记录

共享业务编辑服务在人工改变角色设备关联或数量分配时记录 `manual_edits.requirements`。重新生成保留这些关联，即使目标设备最初由生成器创建，也不再覆盖。

与配套目标不一致时保留人工关系并返回提案冲突；指向同一设备的数量分配形式不误报冲突，也不被改写成单设备形式。取消关联或删除设备后清理对应标记。标记随配置进入草稿、保存修订、版本对比和撤销，不影响物料数量。

### R2：待确认理解进入共用检查

未确认的 Agent 需求理解由共用计算产生 `interpretation_unconfirmed`，包含稳定来源 ID、对象、字段、原文和可选回答。完整检查、增量调价和提案复用同一结论；采用提案后不再丢失该待办。

草稿仍允许保存，正式确认要求解决待办。明确确认或不采用后检查恢复。修复前保存的旧检查在首次正式确认时，也使用固定配置重新核对这项需求；不刷新历史产品或报价，不改写旧记录。已有确认回执的幂等返回保持原行为。

### R3：人工配套分配不再由 ID 格式决定是否重置

通过配套关联或已含抵扣接口重建记录时，单独记录人工修改标记。因此沿用原生成 ID 的数量及依据也会保留。已有的配套分配和已含抵扣共用此机制。

对已有人工分配的需求，重新生成保留明确分配量，返回未满足的缺量，让调用方明确补齐或调整；不会为了填满需求覆盖人工数量、依据或改动现有采购。未人工修改的生成记录仍按原流程重新计算。
