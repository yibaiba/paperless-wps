# 产品搭配知识与项目配置：实现与验收记录

日期：2026-09-24；更新：2026-09-26。依据：用户批准的阶段改造计划。

## 已实现的功能

- 产品身份、具体配置、原始来源分层；来源全量核对、同型号提示、跨来源参数/价格/备注差异；逐条或批量关联、分别建立独立配置、明确阻塞及修订记录。独立整理继承原来人工维护的系列/功能/接口/适用系统及依据，不推断未知参数。
- 适用、配件、共用关系；类型化条件、明确排除配置、草稿/确认/停用、批量编辑和历史。候选明确区分已知检查通过、冲突和资料不足。已确认规则同时存在冲突时不会按修改时间覆盖。
- 搭配知识新增三步快速录入：先选择产品和业务关系，再确认数量与可选限制，最后填写依据和确认状态。常见配套默认按每设备 1:1，特殊数量、条件和清单分类按需展开；原高级编辑器继续处理类别、系列、排除项和完整条件。确认知识缺少候选或必填依据时自动返回对应步骤显示错误。
- Excel 来源、文字 PDF 页码、粘贴文本段落；手动启动提取、任务/逐段状态、失败及中断标记、人工重试、原文对照编辑、接受/拒绝。模型输出不直接变成已确认知识。人工和审核接受共用产品、关联及知识业务服务。
- OpenAI 兼容连接设置、实际连接测试、后端私有密钥文件。模型上下文只包含选定产品/配置和选定 Excel 来源关联的配置；没有选择的其他产品不会发送。提取不参与实时选型计算。
- 房间、系统、角色需求、实际设备实例；需求筛选、显式共享、容量合计、软件/授权独立项目行；按 ZEN 固定公式提供配套建议，应用建议保留来源且不重复补料。统一设备使用投影同时覆盖角色直连和配套分配，供检查、清单和页面共用。
- 项目统一计算“项目需求 → 产品选型 → 配套与缺件 → 方案校验 → 清单与输出”五阶段状态。配置变化后状态立即失效，重新检查才更新；存在冲突或资料不足时只允许形成草稿，不能标记为确认版。
- 项目检查同步生成业务清单投影，逐项保留型号、规格、类型、数量、服务系统与角色、原资料价格字段及工作表行号。共享设备只形成一条清单行；业务清单和拓扑都读取同一项目配置。系统不会在多个价格字段中自行选择报价口径。
- 配套知识统一维护需要什么、替代候选、计算范围、数量输入、公式、清单类型和分配方式。不完整草稿可保存并列出缺项；已确认关系必须完整。旧配套规则提供带行锁和确定标识的并发幂等迁移，迁入后仍保留旧规则和历史。
- 配套计算按设备、系统、房间或整个项目汇总。已有设备通过显式分配抵扣；耗用型数量不能重复占用，共享型设备保留共用依据和容量检查。旧计算版本继续按原语义读取，只有“按最新资料重新检查”才升级草稿。
- 统一项目配置、清单投影、draw.io 图纸、统一撤销/重做、版本保存及并发冲突。设备右侧属性同步图纸标签；布局调整不触发配套计算。普通复制保留引用，复制为新设备才增加采购项。图形删除不删除设备。
- 统一项目只从配置编辑器修改和应用配套，旧清单页是只读投影，旧配套计算接口明确拒绝统一项目。旧项目继续使用原流程；旧清单兼容接口仍写入同一配置聚合。旧独立拓扑保留，旧图导入预览不修改原图。

## 页面入口

| 入口 | 用途 |
| --- | --- |
| `/organize` | 全量来源核对、产品/配置维护、批量归属与版本 |
| `/knowledge` | 搭配知识、条件、例外、批量修订 |
| `/extraction` | 资料、任务、审核、模型设置 |
| `/projects/:id` → 需求选配与拓扑 | 新项目统一配置编辑器 |
| `/configuration/:id` | 项目角色候选、部署、清单、图纸和检查 |

已有页面和接口继续存在。新配置项目的旧清单页面只读并引导进入统一配置；未迁移旧项目保持原流程。旧规则页面只读保留版本历史，新增和维护统一从搭配知识完成。

## 实际数据状态，不能与软件测试混淆

本地工作簿包含 **459 条来源**，全量核对接口覆盖 **459/459**，其中 **410 条**关联已确认配置、**49 条**明确阻塞、未处理为 **0**。阻塞来源保留原因、依据、维护人和修订历史；同型号没有自动合并。五套无纸化工作表的 144 条来源已全部建立具体配置归属。

“分别确认为独立配置”只确认身份和来源，不等于参数提取完成，更不等于整套兼容认证。跨来源差异保留原文核对，价格不自动择一覆盖；总表第 33 行字段异常保持原始证据，没有生成虚构配置。

统一知识库现有 **201 条**记录：120 条已确认、79 条草稿、2 条停用；包括 119 条适用、81 条配套和 1 条共享关系。唯一共享关系仍为草稿，已确认共享知识为 0 条。5 条旧规则保持原状态和历史。红盾 Windows 与会议预约的跨系统服务器关系只有来源支持的候选草稿；常规/国产服务器兼容、跨系统共享、授权和完整配套仍需资料或维护者确认，不能据软件流程通过宣称整套方案已验收。

## 部署与数据迁移

升级后运行：

```sh
.venv/bin/python scripts/migrate_configuration.py
.venv/bin/python -m uvicorn presales.main:app --host 127.0.0.1 --port 8016
```

后台任务另开一个进程：

```sh
.venv/bin/python -m presales.configuration.extraction.worker
```

迁移增量维护 `configuration_entities`、`configuration_revisions`、`configuration_source_links`、`configuration_source_blocks`、`configuration_source_revisions` 和 `configuration_extraction_jobs`，不重建数据库或改写旧来源。项目配置和清单投影在同一事务保存。所有业务更新携带预期版本，PostgreSQL 行锁与修订唯一约束保证竞争更新不会覆盖。

项目冻结产品、配置、来源及知识版本；完整知识快照有不可变标识，不能通过移除一条冲突知识来伪造通过。资料更新后当前检查显示版本差异；“按最新资料重新检查”更新草稿，保存后才形成项目新版本。

密钥保存在 `data/private/model.json`，文件权限 0600，目录 0700，`data/` 已被忽略。接口和校验错误不回显密钥，浏览器不持久保存密钥。更换服务地址时不会自动携带原服务密钥。任务仅用数据库排队，无 Redis；工作进程使用本地文件锁防止重复启动，SIGTERM/重启标记中断并支持重试未完成段落。

## 检查语义

- 同一配置可承担多个系统角色，但采购数取实际部署项，不按型号合并。
- 共用实例数量为 1；多台独立设备各有 ID。共享依据缺失时可以保存，结果为待确认，业务输出只能标记为草稿。
- 已确认、同单位资源需求按设备汇总。单位不同或缺数据为资料不足，不进行隐式换算。
- 需求环境与已知产品参数对照；可选环境使用集合条件。数值范围和带单位条件由普通代码判断，不执行用户/模型代码。
- 旧 `per_group` 迁移后必须明确映射到系统、房间或项目范围；无法确定时保持不完整草稿。
- 新配置的数量输入可取范围内设备数量或明确的需求参数；公式继续由 ZEN 执行每单位乘系数、按容量向上取整和范围内固定数量。
- 已应用配套以需求和实际设备标识关联，重复应用不增料；数量减少后已有配件不自动删除。删除需求来源时，对应需求失效的分配会明确清理，保存重开不残留悬空关系。
- 图形位置、外观、普通副本不改变业务配置。绑定图形的名称/数量在右侧属性编辑，避免图中文字与业务事实冲突。
- 旧共用图形如果表示多台，导入预览会明确要求核对单台实例映射，不猜测每台服务范围。
