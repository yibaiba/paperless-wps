# 产品搭配知识与项目配置：实现与验收记录

日期：2026-09-24。依据：用户批准的四阶段改造计划。

## 已实现的功能

- 产品身份、具体配置、原始来源分层；来源全量核对、同型号提示、跨来源参数/价格/备注差异；逐条或批量关联、分别建立独立配置、修订记录。独立整理继承原来人工维护的系列/功能/接口/适用系统及依据，不推断未知参数。
- 适用、配件、共用关系；类型化条件、明确排除配置、草稿/确认/停用、批量编辑和历史。候选明确区分已知检查通过、冲突和资料不足。已确认规则同时存在冲突时不会按修改时间覆盖。
- Excel 来源、文字 PDF 页码、粘贴文本段落；手动启动提取、任务/逐段状态、失败及中断标记、人工重试、原文对照编辑、接受/拒绝。模型输出不直接变成已确认知识。人工和审核接受共用产品、关联及知识业务服务。
- OpenAI 兼容连接设置、实际连接测试、后端私有密钥文件。模型上下文只包含选定产品/配置和选定 Excel 来源关联的配置；没有选择的其他产品不会发送。提取不参与实时选型计算。
- 房间、系统、角色需求、实际设备实例；需求筛选、显式共享、容量合计、软件/授权独立项目行；按 ZEN 固定公式提供配套建议，应用建议保留来源且不重复补料。
- 统一项目配置、清单投影、draw.io 图纸、统一撤销/重做、版本保存及并发冲突。设备右侧属性同步图纸标签；布局调整不触发配套计算。普通复制保留引用，复制为新设备才增加采购项。图形删除不删除设备。
- 原有清单修改及旧规则补料写入同一配置；旧独立拓扑保留。旧图导入预览保留布局、图形样式、设备来源、系统分组和共享引用，不修改原图。

## 页面入口

| 入口 | 用途 |
| --- | --- |
| `/organize` | 全量来源核对、产品/配置维护、批量归属与版本 |
| `/knowledge` | 搭配知识、条件、例外、批量修订 |
| `/extraction` | 资料、任务、审核、模型设置 |
| `/projects/:id` → 需求选配与拓扑 | 新项目统一配置编辑器 |
| `/configuration/:id` | 项目角色候选、部署、清单、图纸和检查 |

已有页面和接口继续存在。新配置项目的旧清单入口会写回统一配置；未迁移旧项目保持原流程。

## 实际数据状态，不能与软件测试混淆

本地工作簿包含 **459 条来源**，全量核对接口已覆盖 **459/459**，其中 93 条来源涉及原有资料问题（不代表 93 个独立错误）。**已由维护者确认的新归属为 0 条，待确认 459 条。** 实现没有擅自归并同型号，也没有把测试服务器兼容规则写入业务库。

“分别确认为独立配置”只确认身份和来源，不等于参数提取完成，更不等于整套兼容认证。维护者可先批量确认确实独立的来源，再把明确重复的来源关联到同一配置。跨来源差异保留原文核对，价格不自动择一覆盖。

常规/国产服务器、无纸化/会议预约的真实兼容条件、容量、共享依据，以及全量来源归属，需要有资料或维护者确认后验收。当前项目浏览器验收使用隔离数据，不能代替真实业务验收。

## 部署与数据迁移

升级后运行：

```sh
.venv/bin/python scripts/migrate_configuration.py
.venv/bin/python -m uvicorn presales.main:app --host 127.0.0.1 --port 8016
```

后台任务另开一个进程：

```sh
.venv/bin/python -m presales.configuration.extraction.worker
```

迁移仅增加 `configuration_entities`、`configuration_revisions`、`configuration_source_links`、`configuration_source_revisions`、`configuration_extraction_jobs`，不重建数据库或改写旧来源。项目配置和清单投影在同一事务保存。所有业务更新携带预期版本，PostgreSQL 行锁与修订唯一约束保证竞争更新不会覆盖。

项目冻结产品、配置、来源及知识版本；完整知识快照有不可变标识，不能通过移除一条冲突知识来伪造通过。资料更新后当前检查显示版本差异；“按最新资料重新检查”更新草稿，保存后才形成项目新版本。

密钥保存在 `data/private/model.json`，文件权限 0600，目录 0700，`data/` 已被忽略。接口和校验错误不回显密钥，浏览器不持久保存密钥。更换服务地址时不会自动携带原服务密钥。任务仅用数据库排队，无 Redis；工作进程使用本地文件锁防止重复启动，SIGTERM/重启标记中断并支持重试未完成段落。

## 检查语义

- 同一配置可承担多个系统角色，但采购数取实际部署项，不按型号合并。
- 共用实例数量为 1；多台独立设备各有 ID。共享依据缺失时可以保存，结果为待确认。
- 已确认、同单位资源需求按设备汇总。单位不同或缺数据为资料不足，不进行隐式换算。
- 需求环境与已知产品参数对照；可选环境使用集合条件。数值范围和带单位条件由普通代码判断，不执行用户/模型代码。
- `per_unit` 为每件乘系数；`per_capacity` 为数量除容量向上取整；`per_group` 在新配置中为每个部署项最低数量。
- 已应用配套以父设备与知识标识关联，重复应用不增料；数量减少后已有配件不自动删除。
- 图形位置、外观、普通副本不改变业务配置。绑定图形的名称/数量在右侧属性编辑，避免图中文字与业务事实冲突。
- 旧共用图形如果表示多台，导入预览会明确要求核对单台实例映射，不猜测每台服务范围。

## 验证结果

自动测试和浏览器记录见 [configuration-verification.md](configuration-verification.md)。测试环境与业务库分开。真实模型尚未配置，因此真实网络提取、真实资料准确率与业务归属验收仍未完成。

首版不包含 OCR、完整音视频线材计算、定制制造报价、OA/微盘接入和自动全局最优选型。
