# 红盾推荐与 Tab 流畅性实施记录

本轮沿用单元格浮层和共享业务引擎。工作分四阶段：基线、行状态及问题入口、增量计算及异步诊断、资料预览与验收记录。每阶段独立提交，不自动推送；知识整理只生成维护预览。

## 可重复性能基线

入口：`wps-addin/tests/context-benchmark.mjs`，生成 1,000 个已确认产品行，对同一份数据运行一次冷查询、50 次纯查询及 50 次单行数量编辑。测试宿主仅在 tests 目录，结果不能代替 WPS 真机。

修复前本机结果：冷查询 29.45ms，纯查询 p95 20.19ms，编辑后 p95 20.25ms；整表读取 1 次、单行读取 152 次、绑定字段访问 50,550,601 次。字段访问计数揭示扫描对每行线性查找绑定的重复成本；时间数据只衡量请求组装，不含 API、渲染或宿主写入。

新增四项未解析行 HTTP 用例首次均失败：当前未知行、无关区域未知行、未同步旧设备保留、伪装归属。原协议拒绝 `unresolved_rows`，后续实现必须通过服务端依赖检查处理该字段，正式同步继续拒绝带未知行的局部请求。

## 验收边界

真实业务验收需要三类模板、30 条人工核对轨迹及证据。目录序列、合成负载和浏览器替身单列统计。macOS WPS 和登记后的 Windows 实际构建需要分别完成连续接受、原生 Tab、IME、焦点、滚动、多窗口和撤销矩阵；未运行的项目标记未验收。

## 行状态与问题入口

预览可携带未解析行的位置、原身份和上次确认快照；它们不进入删除列表，也不以旧数量证明当前需求已满足。服务端按照当前依赖闭包和设备真实用途判断相关性，不能通过换一个系统提示隐藏已关联设备。正式同步不接受这个局部协议。

问题动作只导航到已有身份、业务设置、模板和固定知识详情，不执行写入或确认规则。动作包含预期本地、绑定及模板修订，过期动作要求重新预览。资料详情显示规则身份、修订和出处，不提供自动发布。

扩大回归曾发现库存首次关联补齐快照被当作单元格换型；已将纯固定快照补齐与业务字段变化分开，库存和供货不变。修复后的相关后端批次分别为 18、26 项通过（每批 60 秒硬超时），前端全套 190 项通过，生产构建及 Ruff 通过。还未据此计入真实业务或宿主验收。
