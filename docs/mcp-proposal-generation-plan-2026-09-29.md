# MCP 需求驱动方案生成扩展计划

状态：待实施。2026-09-29 基于现有 Lists facade、SystemsList、SystemSetup、项目检查和价格版本服务核对。本次仅规划，不发布真实知识或价格。

## 1. 目标与范围

让外部 Agent 完成客户对话、文件理解、需求整理与解释，业务系统完成结构化需求校验、产品组合、配套数量、容量、价格、版本和导出。

目标流程：需求 → 可恢复需求草稿 → 系统生成建议方案 → 解释取舍/处理缺口 → 原子采用 → 检查 → 保存与导出。普通任务不要求售前逐一指定产品型号。

首版业务范围为红盾 Windows 无纸化和会议预约，先验独立部署，再验有确认依据的共享。仅计算已有依据的辅材和授权，不宣称覆盖完整音视频接线或非标制造。保留 Python 模块化单体、ZEN、Decimal、Ant Design、Univer、draw.io、本机 stdio MCP，不引入 LLM 决策、求解器或新常驻服务。

当前业务库四个知识包均为草稿；44条已确认配套中仅2条单独确认数量依据；共享已确认0条，配置已含内容0条。软件验收使用隔离数据，真实生成验收必须明确知识覆盖范围，不能为了通过测试发布业务结论。

## 2. 职责与结构化需求

外部Agent可读取客户资料并提交提取结果，不能把模型推断的规格、容量、兼容或数量公式写为正式知识。需求记录包括房间、系统版本、功能、规模、环境、尺寸限制、预算口径、部署偏好、允许复用的已有设备、明确指定/排除产品。原文引用、用户明确要求、Agent待确认理解分别标注。

房间/系统用稳定ID，创建支持调用方稳定client_key以避免对话重试重复建立；同名不同房间不合并。系统版本有歧义时返回具体可选版本；技术键和单位来自systems_list的需求描述，客户不填写规则ID。未知不等于false、0或不需要。

按现有definition/profile扩展角色数量绑定：输入来自已登记规模字段或已确认固定值，带单位、作用范围、依据和修订。终端32席→32台、软件1套等均必须有明确依据，不能把资源容量指标直接当采购数量。规则可复用现有受控数量计算，不执行Agent提交的公式。

结构化问题包括question_id、code、target、field、scope、recipient、choices、evidence_refs、blocking_effect。recipient区分客户/项目人员与内部知识维护者。客户确认席位、安装形式、国产或功能要求；兼容、授权计量、服务器容量、共享依据等属于内部资料缺口。回答只更新当前需求，不自动创建公共知识。

## 3. 共用方案生成服务

新增 projects/planning 业务模块，注入仓储、固定计算上下文和现有数量引擎；HTTP与MCP调用同一应用服务。

顺序：固定需求/配置/知识/价格修订 → 展开必要角色及数量 → 按硬条件筛候选 → 按选型策略组合 → 递归展开必需配套 → 分配已有及已含内容 → 计算容量和采购 → 全量检查 → 返回可解释提案。

候选优先使用明确适配且数量/资料条件满足的配置；未知和冲突不能作为已验证依据。用户指定但未知的产品可保留在未完成提案中并注明。建议项/可选项独立展示，只有需求功能明确启用或调用方明确采用才加入采购。软件与授权独立计量，共用硬件不合并软件许可。

选型策略固定修订，首版包含维护者确认的推荐顺序、需求明确允许的已有设备复用、指定价格列和日期下的费用偏好、独立/允许共享的部署偏好。硬约束先于偏好。预算未给或缺价时不声称最低价；缺少排序依据时返回可比较候选分支。等价结果稳定排序，明确为同等候选，不把ID顺序当业务优劣。

组合不能只取每个角色第一条候选：遇到后续配套或容量冲突时回溯相关候选，再做完整检查。首版承诺找到已覆盖范围内有依据的可行方案，不承诺全局最低价或任意规则问题最优解。未找到候选与已证明条件矛盾分开表述。

共享用现有设备使用投影、共享规则和资源合计；缺依据不能判通过。独立部署可形成有依据方案时继续产出独立方案，明确列出共享分支缺口。尺寸、接口、安装条件使用现有属性和明确关系，不能仅凭型号相似推定可配。

生成不写项目设备清单。提案保存需求修订、知识/产品/价格引用、生成策略修订、结果、检查摘要、逐行依据、依赖图及指纹。结果分为通过已知检查、部分生成待补资料、明确条件冲突；程序失败/中断单独记录并报错，不伪装业务无解或成功空表。必需项数量未知时保存缺口占位，不创建零件数或默认一件设备。

## 4. MCP和HTTP契约

保留现有十个工具名称、旧参数和摘要分页行为，新增list_plan一个工具。

| 工具 | 扩展 |
| --- | --- |
| systems_list | 返回固定资料版本、角色、需求字段、数量绑定、支持范围和缺口 |
| list_create | 继续建立独立Agent草稿或基于保存版本改单 |
| list_update | 新增requirements_patch、proposal_apply；现有细粒度操作保留 |
| list_plan（新增） | 根据draft_id/expected_revision/operation_id生成持久提案，返回proposal_id、方案摘要、缺口与指纹；不应用设备 |
| list_get | 增加proposal/proposal_lines/decisions/questions视图，通过proposal_id分分页按需读取 |
| list_check | 复用完整检查，统一结构化缺口和处理动作 |
| list_save/list_export | 保留现有保存修订、固定模板和产物逻辑 |
| catalog_search/catalog_get | 继续用于说明、替代候选详情及来源追溯 |

list_plan明确为写入提案的操作，不伪装只读查询；重试同operation_id和内容返回原结果。生成基于不可变输入，计算结束再次验证草稿基线，变化则返回明确过期结果，不挂成当前有效提案。失败和中断可人工/Agent明确重试，不能假完成。

proposal_apply只收proposal_id、所选方案、允许的选项、expected_revision、指纹、operation_id；不接收自算金额、来源快照或任意公式。改变关键输入或候选需先更新需求再生成新提案。

示例调用：systems_list → list_create → list_update(requirements_patch) → list_plan → list_get(questions/decisions) → 外部Agent追问 → list_update → list_plan → list_update(proposal_apply) → list_check → list_save → list_export。需求已明确且任务授权涵盖做单时，Agent可整批采用，不增加每行人工确认步骤；保存/导出不自动代表人工业务认证。

## 5. 应用、改单和版本保护

Configuration仍是实际配置唯一事实来源，提案是待采用结果，不建立可独立修改的第二份正式清单。采用后服务端生成稳定设备ID、用途和配套分配、供货和报价引用、相关图纸对象引用；一个原子批次、一个撤销步骤，重复应用不新增设备。

新增设备没有明确供货口径时保留待分配。若需求明确本次新增采购，可随采用建立采购分配；已有设备按允许复用范围抵扣，不能同一数量重复占用。

记录行级生成来源和人工锁定，区分生成配置与人工添加项。改单保留设备身份，先计算增减、更换、分配和价格差异；人工型号/数量/调整价默认保留，冲突明确列出。减少需求时展示多余项及是否移除，不静默删客户已有或人工设备。布局修改不重算采购。图纸、清单、报价同步进入现有历史。

项目和提案固定知识、产品、价格引用；明确刷新后预览变化。生成后价格发布不静默改已采用金额；资料更新不改旧项目。采用时校验草稿版本和所用快照；需要刷新必须重新生成/明确刷新，不能用最新资料偷偷替换。

## 6. 后台与业务知识收口

后台增加提案预览及需求/缺口查看入口，复用项目清单、检查、差异和来源面板。维护者可核对资料范围和选型策略，无需新增完整对话产品或另一套知识库。

先整理红盾Windows独立部署：角色必要性、候选适用、角色数量、授权及已含内容、服务器容量、已有依据的辅材。以已确认范围形成可发布版本。再接会议预约及跨系统共享。每个维护缺口定位资料、产品或关系，真实缺失由维护者确认，历史同单出现不能作为兼容或数量公式依据。

## 7. 交付与验收

阶段一：结构化需求契约、问题分流、角色数量绑定及systems_list/list_update扩展，Agent可提交需求并得到可回答的问题。
阶段二：独立部署生成服务、持久提案、逐行依据、list_plan和原子采用，完成红盾试点。
阶段三：配套递归、已有/已含抵扣、共享分支和改单，接入会议预约并完善双系统验证。
阶段四：网页查看、MCP全流程、知识范围核验与真实方案对账。

测试覆盖：无需手工指定型号的生成；32席改48席；安装/尺寸/国产/环境条件变化；指定型号与预算冲突；必需项全部展开、未启用可选不采购；替代分支回溯与配套循环；独立两台/明确共享一台/客户已有服务器；软件授权独立；缺数量/缺价/待询价/共享缺依据；人工项保护；同型号多配置不混；同输入同版本结果稳定；过期提案、重复采用、并发、重启恢复；HTTP与MCP一致；撤销、保存、重开、图纸、模板及旧版本不变。

后端每项及每批60秒硬超时；前端类型、构建及必要投影测试；隔离数据库真实stdio MCP和浏览器端到端，留截图。业务库不注入测试规则。真实客户方案逐项对账与桌面Excel/WPS重算单独验收。通过已知检查始终说明知识覆盖范围，不等于整套工程认证。
