## 真实浏览器流程（隔离环境）

同一应用代码，独立 SQLite 文件，接口 8017 / 前端 5177，不写业务库：

1. 从无纸化“服务端”查看候选，选择一个配置后清单只有一项。
2. 会议预约明确关联已有设备，清单仍为一台；两个角色合计需求 80GB，64GB 实例显示资源冲突；无已确认适配依据的角色显示资料不足。
3. 图纸生成设备，选择图形在右侧编辑业务名称，标签同步。
4. “复制为新设备”增加一项；一次撤销同时恢复设备数和图形。
5. draw.io 原生复制图形保持实际设备数不变；保存后重新打开，2 个部署项与 3 个图形引用保持一致。
6. 产品身份编辑成功；搭配知识编辑成功并增加版本。
7. 粘贴文本资料不会自动启动模型；审核夹具能显示原文、编辑草稿、由人工填写审核人/依据后接受，并锁定为已审核。
8. 统一流程隔离验证：一个角色默认只显示相关候选，选用一项后清单只有一项；配套卡显示需要 1、已分配 0、还缺 1，应用后清单为两项并变为已分配 1、还缺 0。
9. 保存后从新页面重开，项目名称、两项清单和分配状态一致；删除需求来源后配套需求消失，撤销同时恢复来源设备和分配，再检查恢复为已分配 1、缺量 0。
10. 统一项目的旧清单页仅显示同一份清单投影和“在配置中查看”，不再提供旧配套计算、添加、编辑或移除入口；旧规则页只提供历史查看和统一知识入口。
11. 跨系统隔离试点保存两套服务端软件和一台共享服务器；服务器行同时显示红盾 Windows 与会议预约两个配套角色，64GB / 12 核需求在 128GB / 32 核服务器上通过，共用部署因没有已确认共享依据保持“资料不足”，待确认事项为 1 条。

第 7 项使用明确标识的审核界面夹具，任务显示未调用真实模型，**不是实际模型提取成功的证据**。

浏览器发现并修复：draw.io 程序同步回传产生多余撤销项；产品列表摘要不足以全量核对；项目保存后查询缓存仍保留旧版本；项目保存响应缺少名称导致标题暂时为空；已满足配套仍显示接近零的数量输入；统一项目仍暴露旧配套入口；删除需求来源后可能留下失效分配。
