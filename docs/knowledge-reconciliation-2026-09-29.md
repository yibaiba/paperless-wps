# 归属与数量集中核对

本轮完成此前优化建议中优先级最高的两项维护能力。入口为“搭配知识 → 按系统版本维护 → 选择系统 → 核对归属与数量”。没有新增依赖、数据库表、计算引擎或另一套知识库。

## 行为

- 使用选定知识包固定的角色定义，显示包内关系修订与当前关系修订，不静默切换到最新定义。
- 历史文字同名只显示提示；目标角色和要应用的行都由维护者明确选择。
- 归属修改复用已有批量预览／应用服务、预期修订及幂等回执。保留原关系状态、数量状态、计算语义版本、条件、排除配置和资料引用；归属核对人、依据及修改前身份记录在既有 identity_mapping 字段中。
- 显示各知识包固定引用，跨系统已有归属明确提示改变适用范围。通用配套不强制指定角色，共享关系仍使用多角色高级编辑。
- 数量专用表单只编辑候选、范围、输入、公式、数量结论、数量依据、引用及维护人。原关系状态、条件、触发条件、需求标识、共享和分配方式保持原值。
- 原文与数量表单并排，可以增加准确来源引用；未知公式保持空值。确认数量继续接受后端完整性校验，不增加默认系数。
- 保存关系后可以直接整理知识包变更，逐项采用新修订。未选关系、其他知识包及历史项目仍保留原版本。

## 验证

- 后端 9 项通过：归属批次重试／过期修订、原证据及包固定修订保持、未知数量保存、缺依据拒绝确认，以及知识包预览和准备情况回归。单项及整批均设置 60 秒硬超时。
- 前端全部 50 项通过，新增 4 项测试覆盖字段所有权、同名跨系统不推定、固定修订与当前记录分离及数量空值。
- TypeScript、生产构建、Ruff 和 git diff --check 通过。已有 Univer 大包提示仍存在，本轮不优化体积。
- 隔离 SQLite（8017）与浏览器（5177）实测：默认不选关系；显式选择角色后预览应用；未知数量保存后仍为空；知识包仅采用选中关系 v2，未选配套仍引用 v1；角色定义仍为 v1，而当前定义已有 v2；另一知识包仍引用关系 v1。
- 浏览器发现批量应用多携带预览返回字段导致 422，已改为仅提交契约规定的字段，并实际重跑保存成功。
