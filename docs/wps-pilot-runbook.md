# WPS Cursor 式补全试点运行手册

## 发布门槛

试点必须同时满足以下条件，不能以浏览器预览或自动化测试代替真机结果：

- macOS WPS `12.1.28496` 全部通过。
- 售前实际 Windows WPS 构建号已登记并全部通过；未登记时不得开放试点。
- 后端 WPS 测试在 60 秒内通过，前端测试、构建及高危依赖审计通过。
- 40 例目录序列回归通过；它与建序数据同源，不能证明真实业务准确率。业务门槛必须由独立项目操作轨迹衡量 Top-1 ≥ 95%、Top-3 = 100%、错误直接写入为 0、可判定灰字覆盖率 ≥ 80%。

## 双平台真机矩阵

在同一份已映射并确认来源的测试工作簿上逐项记录“通过/失败、WPS 构建号、操作者、时间、诊断会话 ID”：

1. 安装加载项，连接个人账号，重启 WPS 后确认无需重新配对。
2. 验证 Ribbon、任务窗格、字段映射、来源范围确认、项目绑定和隐藏元数据。
3. 分别用中文输入法和英文输入型号/名称；IME 组合期间 Tab、Enter 和方向键不得误触发。
4. 唯一候选一次 Tab 写入受管列并进入下一产品行；同型号多配置第一次 Tab 只展开。
5. 使用 `CRIR-D-*` 已确认来源连续接受 20 行，检查无重复、回跳、丢焦点和漏写。
6. 在无候选单元格连续执行 100 次 Tab，行为必须与原生 WPS 一致。
7. 验证滚动、缩放、移动窗口、上下展开、切换工作表、多窗口和休眠恢复。
8. 验证公式、合并单元格、数量、备注及未管理列没有被改写。
9. 断开网络后确认错误明确显示；恢复网络后诊断和反馈队列成功重试。
10. 验证另存副本保留绑定且明确展示原项目，重新绑定与另存为新项目行为正确。
11. 验证同步预览、版本冲突、重复提交和成功后隐藏元数据恢复。
12. 卸载加载项，确认 Tab 已恢复且没有遗留浮层或全局快捷键。

## 两周试点

- 人数：5 名售前。
- 模板：3 类结构不同的真实报价或改单模板，每份先确认目录批次与来源工作表。
- 周期：连续 2 周；每天确认诊断上传是否正常，失败必须记录原因，不能按成功统计。
- 硬指标：候选 API p95 ≤ 500ms；灰字出现后写入 ≤ 100ms；自动写入错误数为 0。
- 准确率：统计可判定空白下一行的灰字覆盖率、Top-1、展开选择次数和无候选次数。
- 任何错误自动写入立即暂停扩大范围，保留诊断会话 ID，修复后重跑后端、前端和完整双平台矩阵。

## 数据与清理

诊断只保留匿名结构化事件 30 天。生产环境每天执行一次：

```sh
.venv/bin/presales-wps-purge-diagnostics
```

试点结束后确认不存在超过 30 天的 `wps_diagnostic_events`，并归档双平台矩阵、三模板结果和暂停/恢复记录。诊断记录不允许补充原始查询、客户名称、工作表文字或备注。
