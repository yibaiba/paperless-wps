# 已有设备部分复用修复与复核

日期：2026-09-29

## 修复范围

- 一个角色可以明确分配多组实际设备；保留旧单设备关联，二者互斥。
- 需求 32、允许复用已有 16 时，仅生成剩余 16。多批已有数量、小数数量、改为 48 或 24 时保留实际设备标识。
- 分配按可用数量扣减，不重复消耗同一批设备。单台服务器仍经过共享和容量检查。
- 角色以及配套的完全复用分支均保留推荐缺口，不把数据库顺序当作公司标准推荐。
- 数量检查、用途、清单、采购、报价、网页表单、删除、撤销及持久草稿共同支持分配关系。

## 代码复核发现及处理

1. 分批角色的配套服务器在用途归并时仍引用临时角色 ID，会误报跨系统共享。改为按原角色 ID 归并，并增加端到端回归。
2. 计算投影展开角色后，进度统计把一个角色计成多个。进度使用原始配置，校验断言需求与已选数量均为一。
3. 同一角色输入可能随设备批次重复贡献到系统级配套数量。按原角色和计算范围去重；设备数量按各批明确分配量贡献。
4. 没有分配关系的普通项目无需深拷贝检查结果；ID 还原在无别名时直接返回。
5. 简单表单及删除设备路径保留剩余分配，不覆盖其他批次或静默删除实物设备。

本轮为主线程自审，未声称执行独立代理审查。复核没有剩余的本次范围内阻塞项。
