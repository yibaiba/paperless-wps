# 知识包选型试查与角色待办贯通

## 本轮交付

- 搭配知识 → 按系统版本维护 → 选择系统 → 可用范围检查 → **选型试查**。
- 选择包内角色、当前产品配置和项目参数，复用项目 `candidate_check_v3` 判断适用性。展示条件满足、明确冲突或资料不足；展开查看原文、规则修订、输入值、比较条件及单位。
- 草稿关系单独提示，不作为通过依据。禁止关系明确显示性质，不能把“禁止条件满足”读成“产品通过”。
- 输入修改立即清除旧结果。请求期间禁用表单，包修订过期返回 409；不存在的角色、配置和重复参数返回明确错误。
- 必要角色检查动作携带角色 ID、名称和功能分支，点击待办后需求表单预填对应角色。
- 项目角色和功能选项优先采用所选知识包固定的系统定义，而非独立定义的最新修订。草稿角色显示“必要性待核对”，不再误写为可选。

## 范围与存储

新增只读计算入口 `POST /api/configuration/knowledge-packages/{identity}/trial`，输入包的预期修订、角色 ID、产品配置 ID 和环境参数。服务复用现有数据访问对象与纯计算函数，不提交数据库变更。

试查使用**包内固定关系 + 当前产品配置**，结果同时返回两者修订。它不是某个历史项目的完整重放；实际项目仍通过自己的快照和检查入口计算，并可能纳入匹配的通用知识。

试查不创建项目、不加入采购清单、不确认关系、不发布知识包。本轮没有新增业务事实或调用模型。可重复案例目前保存在自动化测试中；未新增持久化案例编辑器。

适用条件通过不等于整套清单通过。试查没有执行整套配套数量、共享服务器、资源容量、采购和报价核算；页面保留知识覆盖未完整的提示。
