# Univer 开源核心接入计划

状态：待实施。2026-09-27 已核对现有代码、官方功能边界和 npm 元数据；尚未安装或完成 SDK 验证。

## 1. 首版目标

在现有项目的“报价与模板导出”页增加“工作表”视图，让售前能够用接近 Excel 的方式编辑清单、批量调整报价、查看缺项，保存后导出已有公司模板。

首版针对清单与报价，不改产品库和知识维护入口。业务数据仍由现有项目配置管理，Univer 是同一份配置的编辑视图。

- 使用 Apache-2.0 开源核心，不接 `@univerjs-pro/*`、商业许可证或 Univer 云服务。
- 复用 React 19、Vite、Ant Design、Python、ZEN、Decimal、现有数据库和公司模板导出。
- 不增加 Office 后端或 Node 常驻服务，不依赖 ONLYOFFICE；此前下载的镜像保持未启动，不调整现有检索服务。
- Word 编辑、任意 XLSX/DOCX 文件导入、在线打印、多人实时协同不在本轮范围。
- Excel 复制的矩形文本可以粘贴进已定义的业务列；这不等于读取整个 XLSX 文件。
- 网页工作表用于编辑业务数据，下载的 XLSX 继续保留原公司模板的 Logo、版式、公式和税运说明，不承诺两者像素一致。

## 2. 已有基础与需要补齐的部分

| 已有模块 | 接入方式 |
|---|---|
| `quotation/QuotationPanel.tsx` | 新增工作表视图，保留已有明细视图作为明确的切换选项 |
| `QuotationForms.tsx` | 复用报价抬头、价格列、人工单价依据表单 |
| `useConfigurationDraft` | 所有成功业务编辑共用撤销、重做与未保存状态 |
| `useProjectRequests` | 复用检查、保存、旧结果失效、并发版本保护 |
| `lists/commands.py` | 将可复用业务编辑提取到项目服务层，供网页和 MCP 调用 |
| `quotation/calculation.py` | 保留价格来源冻结、型号变更后价格过期、Decimal 计算 |
| 配套、设备使用、供货投影 | 继续决定缺量、共享和采购数量 |
| 模板与产物服务 | 继续按保存版本生成 XLSX，不从 Univer 快照生成正式报价 |

目前网页编辑在内存项目草稿中，MCP 使用独立服务端草稿。本轮共享业务操作与计算服务，不让网页每次编辑额外建立一个 MCP 草稿。

## 3. 页面和操作

继续使用现有报价页的宽布局，周边表单和按钮用 Ant Design，表格区域用 Univer。

- 顶部：项目与保存版本、采用价格列、撤销/重做、检查、保存、导出。
- 中间：工作表，冻结表头及产品标识列，支持键盘移动、连续编辑、多选和批量粘贴。
- 右侧停靠面板：选中产品的来源、单价依据、供货分配、配套及问题。选择多个产品后保持打开。
- 下方：已知金额小计、完整报价合计或待确认原因、业务检查状态；问题可定位对应行。
- 只加载当前使用的编辑器；加载和运行错误明确展示，不伪装为空表或自动换用另一个编辑器。

首版列与编辑口径：

| 内容 | 操作规则 |
|---|---|
| 产品名称、型号、规格、单位、品牌、服务系统 | 从产品快照和设备使用投影读取；更换产品通过已有候选面板 |
| 部署数量 | 可编辑；遵循现有共享单台设备和数量规则 |
| 本次采购、客户已有、供货待确认数量 | 显示计算结果；点击进入供货分配面板，按分配记录编辑并保留依据 |
| 报价单价 | 可编辑；人工改价要求依据，支持多行共用一次填写的依据 |
| 价格来源、调整依据 | 来源可查看；采用价格列和批量重新采用通过工具栏操作 |
| 报价分区、设备备注 | 可编辑，写回现有 `quotation.sections` 和 `device.note` |
| 行金额、总额、适配/缺件状态 | 计算结果，只读，不能通过粘贴或公式覆盖 |

修改部署数量不自动假定增加的是采购或客户已有。数量增加后的未分配部分显示待确认；减少造成供货或配套超量时明确提示，允许通过分配面板修正，不静默删采购项。

新增、换型、删除使用明确业务操作：新增时选择具体产品配置及来源；删除时处理角色、配套、供货、价格和图纸引用。粘贴一行文本不创建虚构产品，复制一行不自动新增设备。

## 4. 工作表与业务数据同步

唯一事实来源为 `Configuration`。每行稳定绑定 `device_id`，配置和来源继续用各自 ID；不得把行号、型号或名称当主键。

数据流：

```text
项目配置 + 当前检查结果 → 工作表投影 → Univer 显示
单元格修改/批量粘贴 → 明确的业务操作 → Python 编辑与检查服务
成功结果 → 一次提交到项目草稿 → 清单、供货、图纸与报价视图更新
保存修订 → 现有模板导出 / MCP 读取
```

- 屏幕单元格编辑结束后构成操作；不在每次键入时请求后端。
- 一次粘贴构成一个批次：先检查列、数据类型和必填依据，显示变更预览，再一次应用。错误定位行列，整批不发生部分业务提交。
- 尚未应用的粘贴内容是临时输入，不是另一份项目配置；保存前明确应用或取消，不能导出与屏幕输入不同的结果。
- 编辑器排序仅改变显示顺序：首版由受控排序入口重建行与 ID 映射，禁用会使单列与产品身份脱离的局部排序。
- 产品、来源、金额等业务列通过开源命令/权限机制保护；HTTP 服务独立校验输入，不能只依靠 UI。
- 单价与数量按十进制文本传输，保持“空/待确认”与明确的 `0` 区别。业务输入不接收单元格公式，不用 JS 浮点结果生成正式金额。
- 自定义公式和自由合并业务单元格不属于首版操作；避免覆盖价格依据、设备绑定和采购口径。这是本业务工作表的范围，不是 Univer 核心能力限制。

统一撤销：项目草稿历史为权威。单次业务编辑或一次批量粘贴产生一个历史步骤；工作表、项目工具栏的撤销/重做接入同一入口，不保留两套竞争的业务历史。正在输入的文本可以局部撤销，输入提交后进入项目历史。

程序回填、检查结果刷新和重新渲染使用独立来源标识，不反向触发业务修改或新增撤销步骤。异步请求绑定草稿版本；返回时若当前草稿已变化，不覆盖新输入，保留待应用内容并提示重新检查。

列宽、缩放、选区和排序在本轮只作为页面会话状态，不写入业务配置、检查指纹或项目修订；退出重开使用默认布局。后续有明确需求再增加布局持久化。

## 5. 接口与代码边界

新增项目编辑预演入口，接受当前页面配置、草稿版本标识和一批明确操作，返回新配置、检查投影与变更摘要；此接口不写项目版本或产生 MCP 草稿。

建议契约：`POST /api/configuration/projects/{project_id}/edit-preview`，具体前缀与现有 `ROOT` 保持一致。请求含 `configuration`、`draft_version`、`operations`；成功响应原样携带版本标识。错误返回操作索引、设备 ID、字段、错误码和可读原因。

以已有 `price_set`、`price_readopt`、`supply_set` 等语义为基础，补充窄字段的设备修改和报价分区修改操作；工作表不提交行号作为业务标识，也不允许修改产品快照。旧 MCP 操作名称和响应继续兼容。

后端可复用编排放到 `configuration/projects/services/`，DTO 放到项目 schemas；`lists/commands.py` 保留兼容适配。先提取本轮需要的编辑行为，不搬动全部路由或重做服务架构。

前端新增文件放在 `features/configuration/quotation/sheet/`，按编辑器生命周期、工作表投影、事件与操作适配、批量编辑界面划分职责。Univer 实例、命令 ID 和 API 不扩散到产品、知识或 MCP 层。

保存仍用现有项目接口的 `expected_revision` 检查。MCP 或其他窗口已保存新版本时返回冲突，不覆盖。导出继续绑定已保存修订，网页未保存修改不进入导出文件。

## 6. 依赖与性能

- 2026-09-27 npm 核对 `@univerjs/presets`、`@univerjs/preset-sheets-core`、`@univerjs/sheets` 的 stable 版本均为 `1.0.2`，标记 Apache-2.0；作为首轮验证基线，精确锁定版本。
- 核心预设声明支持 React 19，需要 RxJS；按实际依赖声明补齐并锁定，检查锁文件中没有 `@univerjs-pro/*`。
- 只引入所需核心和开源功能插件；若需要直接导入 core/facade，则显式声明对应依赖，不依赖偶然提升的包。
- React.lazy 按需加载工作表；中文语言包本地打包，样式限定在编辑器容器，复用现有 Ant Design 主题。
- 实例放在 ref 中，按官方 React 19 指引处理初始化、事件清理和销毁；不因每次单元格变化重建实例。
- 批量更新走一次业务提交，增量回填受影响区域；视图改变不重算配套。
- 基础可用性先实测，再决定是否需要 Worker；不提前增加服务或性能框架。

## 7. 实施顺序

1. **SDK 小范围验证**：在项目开发环境用隔离数据验证中文、React 19 生命周期、粘贴事件、只读列、取消命令、快捷键与统一撤销接管。确认依赖全部为开源范围，失败明确记录，不隐藏问题。
2. **接入真实业务投影**：报价页加载当前配置和结果，稳定绑定设备 ID；右侧可查看来源、价格和缺项。此阶段验证显示，不宣称已可编辑保存。
3. **编辑与检查闭环**：完成共享编辑服务、单元格及批量操作、价格依据、供货调整、一次撤销/重做、异步结果版本保护。
4. **保存、MCP 与模板回归**：保存重开一致；MCP 能读取网页保存结果，Agent 保存内容能在工作表查看；导出仍为原模板服务生成的报价文件。

每阶段在同一报价功能内推进，不交付一个与业务系统脱节的空白 Excel 演示页。

## 8. 验收

全部使用隔离项目、测试价格和真实资料副本，不向业务库注入测试共享规则。

- 无纸化与会议预约分别部署两台服务器、显式共享一台、客户已有服务器，三种场景数量和金额一致。
- 软件、授权、硬件、配件分别计量；未选候选不进入清单；未知共享依旧资料不足。
- 改数量、改价、换型、分区和备注后，工作表、详情、供货、检查与模板输出一致。
- 空价、零价、小数数量、四舍五入边界、已过期价格、缺少依据分别验证；完整金额以 Decimal 服务结果为准。
- 批量粘贴混合有效/无效值、跨只读列、删除值、粘贴公式均明确处理，不部分提交或静默转换成零。
- 排序后修改目标正确；相同型号的两台设备仍独立；过滤不改变采购数量。
- 单元格编辑、跨视图操作、整批粘贴各自撤销/重做正确；表格程序回填不制造新历史或循环请求。
- 过期检查、晚返回请求、MCP/网页并发保存不覆盖新修改；未应用输入和未保存项目均不会被当成已保存输出。
- 反复切换页面没有重复实例、重复监听或焦点丢失；键盘与多行中文粘贴可用。
- 以 50、200、500 行隔离数据记录首次打开、连续编辑和批量粘贴耗时，作为调优依据，不将其设置成业务数量上限。
- 后端新增单项和每批测试均设 60 秒硬超时；前端执行 TypeScript、生产构建及真实浏览器流程。重点自动化覆盖 ID 映射、十进制文本、原子批次和历史同步。
- 公司模板校验值不变，扩行、Logo、公式、税运说明与原导出回归一致。Univer 验收不是 Excel/WPS 原生显示或重算验收。

完成标准：用户能在项目网页中连续、批量编辑有来源的清单与报价，检查、撤销、保存和导出一致；整个流程不使用商业 Pro 功能，也不新增 Office 常驻服务。
