# 用途检查复用与知识待办（2026-09-28）

这一轮把重复的容量检查从单个项目抽到版本化用途定义。适用关系、配套规则、共享依据仍独立维护；用途检查不代表整套方案已认证。

## 使用

1. 搭配知识 → 用途检查：创建草稿，填写需要的项目输入、产品容量字段、单位、需求系数及来源。明确依据后再确认。
2. 按系统版本维护 → 维护角色定义：角色选择用途检查的固定修订。知识包继续固定其系统定义修订；更新检查后需显式重绑角色、更新知识包。
3. 项目 → 选中系统 → 系统规模与输入：填写系统规模，多个角色复用。保存进入工作草稿，可撤销、重做、正式保存和重开。
4. 搭配知识 → 知识待办：按知识修订/系统版本/角色/配置聚合最新保存项目中的缺口，展开查看影响项目。未保存草稿不进入全局待办。更新资料后仍需项目主动重新检查。

## 计算和历史

- 角色绑定固定检查修订，定义快照内保留检查内容。更新当前用途检查不会修改旧项目。
- 系统输入是 project_input，不与产品同名属性做相等比较。角色同名参数若与系统输入不同，显式报冲突。
- 已确认检查将项目输入乘明确系数投影为资源需求；不写回手工 resources。
- 可把资源交给当前设备或指定 need_key 的配套设备。
- 同一资源仅在单位、合计方式和容量口径一致时比较；支持各用途相加或按最大需求，以及部署整体容量或单台容量乘部署数量。
- 最大需求口径也不能替代共享依据。现有兼容、共享、配套和供货检查继续执行。
- 不足输入、产品容量未知、草稿检查、手工需求与检查重复、知识包与检查结论矛盾均保留明确问题。
- 计算指纹使用原始配置与固定资料版本，与已有增量编辑服务保持一致。
- 旧数据无用途检查引用，继续原路径。无新增数据库表、依赖、模型调用或服务。
